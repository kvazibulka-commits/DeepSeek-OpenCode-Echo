# GigaChat в ЭХО

GigaChat придумывает архетип трека вместо движка правил. Работает поверх уже
готового сервера: если ключей нет или модель недоступна, всё остаётся как
сейчас — ЭХО не ломается и не тормозит.

## 1. Что происходит под капотом

```
плеер → POST /api/signal → сервер сразу ставит архетип из правил
                         → трек уходит в фоновую очередь
                         → GigaChat возвращает JSON {archetype, observation}
                         → сервер обновляет сигнал и кэширует результат
                         → Android видит новый архетип при следующем опросе
```

- Сеть вызывается **в фоне**: приём сигналов не ждёт модель.
- Ответ кэшируется по ключу `артист|трек|альбом` в таблице `track_meta`.
  Один трек — один запрос, сколько бы раз он ни играл.
- Таймаут 8 с, две попытки, при неудаче остаётся архетип из правил.
- В интерфейсе под образом появляется подпись `образ: <модель>`, чтобы было
  видно, что это ИИ.

Код: `server/ai.py` (клиент), `server/echo_server.py` (очередь и кэш).

## 2. Что нужно сделать вам

### Шаг 1. Аккаунт разработчика

1. Откройте <https://developers.sber.ru>.
2. Войдите через Сбер ID (или зарегистрируйте его).
3. Заполните профиль разработчика, если попросит.

### Шаг 2. Проект и доступ к GigaChat API

1. В личном кабинете создайте проект (например, `echo-radar`).
2. Откройте раздел **GigaChat API** и подключите его к проекту.
3. Выберите тариф для физлица (Personal / `GIGACHAT_API_PERS`).
   Для юрлица будет `GIGACHAT_API_B2B` и другой тариф.
4. Дождитесь статуса «активно» — иногда это несколько минут.

### Шаг 3. Ключи

В карточке проекта нажмите **«Получить ключи»** / «Авторизационные данные».
Вам выдадут пару:

- **Client ID** — длинная строка;
- **Client Secret** — ещё одна длинная строка.

Важно: это **не** логин и пароль Сбер ID. Секрет показывают один раз —
сохраните его. Если потеряли, выпустите новые ключи.

### Шаг 4. Передать ключи серверу

Ключи живут только в переменных окружения, в git не попадают.

Временный запуск (PowerShell, перед `run-server.bat`):

```powershell
$env:ECHO_GIGACHAT_CLIENT_ID="ваш_client_id"
$env:ECHO_GIGACHAT_CLIENT_SECRET="ваш_client_secret"
.\run-server.bat
```

Постоянно (один раз, потом перезагрузка консоли):

```powershell
setx ECHO_GIGACHAT_CLIENT_ID "ваш_client_id"
setx ECHO_GIGACHAT_CLIENT_SECRET "ваш_client_secret"
```

Проверить, что переменные видны:

```powershell
echo $env:ECHO_GIGACHAT_CLIENT_ID
```

### Шаг 5. Сертификаты (если будет ошибка TLS)

Windows не доверяет российским корневым сертификатам, поэтому по умолчанию
клиент ЭХО не проверяет TLS для GigaChat. Это нормально для домашней сети.

Если хотите строгую проверку:

1. Скачайте корневой сертификат Минцифры:
   <https://gu-st.ru/content/other/doc/russian_trusted_root_ca.pem>
2. Положите его, например, в `C:\certs\russian_trusted_root_ca.pem`.
3. Задайте:

```powershell
setx ECHO_GIGACHAT_CA "C:\certs\russian_trusted_root_ca.pem"
```

Альтернатива — установить сертификат в хранилище Windows и включить строгий
режим: `setx ECHO_GIGACHAT_STRICT 1`.

### Шаг 6. Проверка

1. Перезапустите сервер.
2. В логе должна появиться строка:

```
GigaChat включён: модель GigaChat
```

Если написано `GigaChat выключен: нет ECHO_GIGACHAT_CLIENT_ID/SECRET` —
переменные не дошли до процесса.

3. Включите новый трек на телефоне или ПК.
4. Через 1–5 секунд откройте паспорт сигнала: под «ОБРАЗ ТРЕКА» появится
   подпись `образ: GigaChat`.
5. В логе будет:

```
GigaChat: Munknörr — Vanir → Дозорный фьорда
```

## 3. Настройки

| Переменная | По умолчанию | Смысл |
|---|---|---|
| `ECHO_GIGACHAT_CLIENT_ID` | — | обязательна |
| `ECHO_GIGACHAT_CLIENT_SECRET` | — | обязательна |
| `ECHO_GIGACHAT_SCOPE` | `GIGACHAT_API_PERS` | физлицо; для юрлица `GIGACHAT_API_B2B` |
| `ECHO_GIGACHAT_MODEL` | `GigaChat` | `GigaChat`, `GigaChat-Pro`, `GigaChat-Max` |
| `ECHO_GIGACHAT_CA` | — | путь к PEM корневого сертификата |
| `ECHO_GIGACHAT_STRICT` | — | `1` — проверять TLS системными сертификатами |

Модель влияет на качество и цену: `GigaChat` — быстро и дешево,
`GigaChat-Pro`/`Max` — литературнее, но расходует больше токенов.

## 4. Лимиты и деньги

- На бесплатном тарифе есть месячный лимит токенов; он виден в личном кабинете.
- Один архетип — примерно 60–100 токенов запроса и столько же ответа.
  Тысяча уникальных треков — это порядка 100–200 тысяч токенов.
- Кэш `track_meta` не даёт тратить токены на повторные проигрывания.
- Если лимит кончился, GigaChat вернёт ошибку — сервер молча оставит архетип
  из правил.

## 5. Приватность

На сервер GigaChat уходят только строки: артист, название, альбом, жанр.
Ни устройств, ни координат, ни откликов. Если это нежелательно — используйте
локальную модель (Ollama) вместо GigaChat; интерфейс `ai.generate` тот же.

## 6. Если что-то не так

| Симптом | Причина | Что делать |
|---|---|---|
| `GigaChat выключен` | переменные не заданы | `setx`, перезапустить консоль и сервер |
| `401 Unauthorized` | неверные Client ID/Secret или scope | перевыпустить ключи, проверить scope |
| `403` | API не подключён к проекту / тариф не активен | включить GigaChat API в кабинете |
| `SSL: CERTIFICATE_VERIFY_FAILED` | нет российского корневого сертификата | задать `ECHO_GIGACHAT_CA` или убрать `STRICT` |
| `429` | превышен лимит | подождать или сменить тариф |
| Архетип не меняется | трек уже в кэше или модель вернула не JSON | удалить строку из `track_meta` и сыграть трек заново |

Сбросить кэш архетипов:

```powershell
python -c "import sqlite3; c=sqlite3.connect('server/echo_memory.db'); c.execute('DELETE FROM track_meta'); c.commit()"
```

## 7. Как это проверяется без ключей

`server/tests/test_ai.py` проверяет разбор JSON, очистку текста, валидацию
архетипа и ключ кэша. Сетевой вызов в тестах не выполняется.

## 8. Что прислать мне

Лучше впишите ключи сами командами из шага 4 — тогда секрет не уйдёт в чат.
Если удобнее, пришлите две строки:

```
Client ID: ...
Client Secret: ...
```

Я пропишу их на этой машине через `setx`, перезапущу сервер и покажу первый
сгенерированный архетип в логе.
